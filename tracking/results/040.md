## Decisions

- Reservation quantities are billed units at the immutable admitted meter rate
- Unlimited capacity is represented explicitly and custom or malformed quota values fail closed
- Usage events and every reservation mutation share one PostgreSQL transaction advisory lock per tenant pool and exact period
- Existing holds retain their admission snapshot across plan changes while new holds use current entitlement context
- Elapsed holds stop consuming capacity immediately and hourly maintenance persists terminal expiry
- Raw idempotency keys are stored only as SHA-256 digests with canonical request checksums

## Remaining risks

- Finalized-event reconciliation inspects at most 10000 rows per hourly run; composite foreign keys and immutable database triggers are the primary consistency enforcement
- Replacing the usage-event integrity function can wait briefly behind an in-flight usage write during deployment
